# Hospital Ops Hub — 사용 매뉴얼 (MVP)

이 문서는 의성한방병원 운영팀이 Hospital Ops Hub 를 **어떻게 쓰는가**를 설명합니다.
기술 구조는 `README.md`, 제품 설계는 `docs_PRODUCT_AND_OPERATIONS.md` 를 참고하세요.

> **현재 단계**: 모든 데이터는 mock store(메모리)에 저장됩니다.
> 브라우저를 새로고침해도 유지되지만, **dev 서버를 재시작하면 초기 샘플로 돌아갑니다.**
> 실 DB / 실 API 연동은 `docs/INTEGRATION_ROADMAP.md` 의 단계별 계획 참조.

## 0. 실행하기

```bash
cd /Users/minions/CRM_MVP_repo
pnpm install           # 최초 1회
cp .env.example .env   # AI 쓰려면 OPENAI_API_KEY 채우기 (아래 0-1 참고)
pnpm dev               # http://localhost:3000 (또는 3001)
```

### 0-1. LLM (GPT) 연결 — 선택이지만 강력 추천

`.env` 편집:
```bash
AI_PROVIDER=openai
AI_MODEL=gpt-4o-mini        # 월 $0.40 내외 (30건/일 기준)
OPENAI_API_KEY=sk-...        # OpenAI API key
```

- `AI_PROVIDER=mock` (기본): 결정형 엔진 — 고정 문구 조합. "환자의 모든 질환을 낫게 한다" 같은 의도 레벨 과장은 못 잡음.
- `AI_PROVIDER=openai`: GPT 호출. 답글 자연스러움 + 의도 레벨 컴플라이언스 이중검사.

품질 부족 시 `AI_MODEL=gpt-4o` 로 승격 가능.

- 서버를 껐다 켜면 모든 샘플 데이터가 **초기 상태로 리셋**됩니다.
- 끄기: 터미널에서 `Ctrl+C`
- 캐시가 꼬이면 `rm -rf apps/web/.next` 후 다시 `pnpm dev`

## 2. 대시보드 (`/dashboard`)

**언제 쓰나:** 출근 직후. 하루에 한 번, 또는 2~3시간마다.

### 상단 8개 카드
| 카드 | 의미 | 클릭 시 이동 |
|---|---|---|
| 오늘 예약 | 오늘 날짜에 잡힌 총 예약 수 | `/reservations` |
| 미확정 예약 | status=new / pending_confirmation | `/reservations?status=pending_confirmation` |
| 30분+ 미처리 | 등록 후 30분 지나도 확정 못 한 예약 | 미확정 예약 필터 |
| 신규 상담 | status=new 인 상담 수 | `/conversations?status=new` |
| 미응답 상담 | new + in_progress 합계 | `/conversations` |
| 신규 리뷰 | 아직 처리 안 된 리뷰 수 | `/reviews?status=new` |
| 답글 대기 | new + draft_generated + needs_review | `/reviews` |
| 민감 이슈 | riskLevel=high 인 리뷰 + 상담 | `/reviews?risk=high` |

숫자가 빨간색이면 **오늘 처리 필수** 항목입니다.

### 하단 3개 패널
- **긴급 리뷰** — 고위험 리뷰 5개 (별점 1~3 또는 부작용/환불/분쟁 언급)
- **대기 예약** — 시간순으로 정렬된 확정 대기 예약 6개
- **신규 상담** — 최근 메시지 순 6개

각 항목 클릭으로 상세 페이지에 바로 진입.

### ⚠️ 노쇼 위험 빨간 배너 (상단)
- 예약 시간에서 **20분 이상 경과**한 `확정 대기` / `확정 완료` / `신규` 예약이 있으면 대시보드 상단에 빨간 배너로 노출.
- 자동으로 status 를 `노쇼 위험` 으로 전환 + 감사로그 기록.
- **카카오 알림톡 발송**은 발송대행사 계약 전이라 현재는 stub 상태 (배너에 "알림톡 미연동 (stub)" 뱃지 표시). 연동 후에는 동일 배너에 "알림톡 발송됨" 뱃지로 바뀝니다.
- 운영자가 전화로 확인하고 "확인함" 버튼을 누르면 배너가 사라집니다.

## 3. 리뷰 인박스 (`/reviews`) — **가장 중요**

**언제 쓰나:** 하루 2~3번. 네이버 리뷰 새로 올라올 때마다.
**핵심 흐름:** `새 리뷰 등록` → `초안 생성` → `컴플라이언스 검사` → `승인` → `등록 완료 처리`

### 왼쪽 패널: 리뷰 목록
- **상태 필터 칩**: 전체 / 신규 / 초안 생성 / 검토 필요 / 승인 / 등록 완료 / 에스컬레이션
- **최소 별점 드롭다운**: 특정 별점 이상만 보기
- 각 리뷰 카드에 별점 · 리뷰어 · 위험도 · 상태 · 시간 표시
- 카드 클릭하면 오른쪽에 상세가 열림

### 오른쪽 패널: 작업 영역
리뷰를 선택하면 다음 요소가 보입니다:

1. **원문** (리뷰 내용, 이미지 첨부 있으면 링크)
2. **메타 배지** (위험도, 상태, sentiment)
3. **답글 초안 textarea** (운영자가 자유롭게 수정 가능)
4. **액션 버튼 4개**

### 액션 버튼 사용법

#### ① 초안 생성 / 재생성
- `AI_PROVIDER=openai` 이면 GPT 호출 → 자연스러운 문장 생성 (같은 리뷰라도 매번 약간 다름)
- `AI_PROVIDER=mock` 이면 결정형 엔진 (같은 리뷰엔 항상 같은 초안)
- 의성한방병원 고정 인사 + 공감 문구 + 다짐 문구 1개 + 고정 마무리
- 별점 1~3, 부작용/환불/분쟁 언급이 있으면 자동으로 `needs_review` 상태
- LLM 호출 실패 시 자동으로 결정형 fallback (사용자는 눈치 못 챔)

#### ② 컴플라이언스 검사 (이중검사)
- **1차**: 키워드 스캔 (BLOCKED 22개 / CAUTION 9개). 빠르고 무료.
- **2차**: LLM 의도 검사. 1차 통과 + `AI_PROVIDER=openai` 일 때만 실행.
  - "환자의 모든 질환을 낫게 한다", "다른 병원보다 앞선 기술", "어떤 증상이든 해결" 같이
    키워드로는 못 잡는 **의도 레벨 과장**을 GPT가 판단.
- 결과:
  - `approved` → 그대로 승인 가능
  - `revision_required` → 자동 수정 제안. "이 수정안으로 교체" 버튼.
  - `rejected` → 수정해야만 승인 가능 (승인 버튼 눌러도 422).

#### ③ 승인
- 최종 문구를 `approved` 상태로 저장
- 내부적으로 한 번 더 컴플라이언스 검사 (blocked 있으면 거절)
- 감사 로그 기록 (누가 언제 승인했는지)

#### ④ 등록 완료 처리
- ⚠️ **네이버 리뷰 답글 자동 등록은 아직 연동 전**입니다. 이 단계는:
  1. 승인된 답글을 복사
  2. 네이버 플레이스에 운영자가 직접 붙여넣어 등록
  3. 등록 성공 후 이 버튼 눌러 상태를 `posted` 로 기록
- `approved` 상태 아니면 버튼이 비활성화됨

### 전형적인 하루 시나리오
```
오전 9시: 대시보드 열고 "신규 리뷰 3건" 확인 → /reviews 로 이동
→ 필터 "신규" 선택 → 첫 번째 리뷰 클릭
→ "초안 생성" → 2~4문장 초안 자동 완성
→ (선택) textarea 에서 직접 문구 다듬기
→ "컴플라이언스 검사" → approved 확인
→ "승인" → 초안이 approved 상태로 저장됨
→ 네이버 플레이스에 직접 등록
→ "등록 완료 처리" → 상태 posted
```

### 특수 케이스
- **별점 1점 + "환불" 언급** → riskLevel=high, sentiment=negative, status=needs_review
  → 자동 승인 금지. 반드시 매니저/원장 검토 후 승인.
- **5점 + 긴 후기** → riskLevel=low, 자동 승인 후보
- **"완치" 같은 BLOCKED 단어 수동 입력 시** → 승인 시 422, 문구 수정 필수

## 4. 상담 인박스 (`/conversations`)

**언제 쓰나:** 카카오 채널/네이버 톡톡으로 새 문의 들어올 때마다.

### 왼쪽 패널: 상담 목록
- **상태 필터**: 전체 / 신규 / 응대 중 / 환자 회신 대기 / 완료 / 에스컬레이션
- **채널 필터**: 네이버 톡톡 / 카카오 채널 / 카카오 비즈 / 수동
- 각 카드에 발신자 · 채널 · 카테고리 · 위험도 · 마지막 메시지 시간

### 오른쪽 패널: 대화 상세
- 발신자 정보 + 마스킹된 전화번호
- 채널/카테고리/위험도/상태 뱃지
- **상태 셀렉트**: 언제든 상태 변경 가능 (감사 로그 남음)
- **자동 분류 버튼**: inbound 메시지를 분석해 카테고리/위험도를 재계산
- 메시지 스레드:
  - 왼쪽 회색 버블 = 환자 발화 (inbound)
  - 오른쪽 초록 버블 = 운영자 답변 (outbound)
  - 가운데 노란 박스 = 시스템 알림 (예: "민감 키워드 감지 → 매니저 에스컬레이션")

### 자동 분류 로직
11개 카테고리 중 하나로 분류:
- **자동응답 후보 (정보형)**: 진료시간, 위치/주차, 예약문의, 비용문의, 준비물복장, 서류문의
- **사람 검토 강제**: 예약변경취소, 증상상담, 불만민원, 환불분쟁
- 민감 키워드(악화/부작용/분쟁/신고) 감지 시 자동으로 `escalated` 상태 + riskLevel=high

### 시나리오
```
카카오 채널에 "치료 후 더 아픈데 환불 가능한가요?" 메시지 도착
→ /conversations 신규 목록에 cv_N 으로 표시
→ 자동 분류 버튼 → 환불분쟁 카테고리, riskLevel=high, escalated
→ 매니저 담당자 배정 (TBD — 현재 UI에 담당자 배정 없음, 추후 추가)
→ 매니저가 직접 전화로 응대 후 상태를 "완료" 로 변경
```

## 5. 예약 보드 (`/reservations`)

**언제 쓰나:** 예약 확정/취소/변경 발생할 때마다.

### 7개 컬럼 (칸반)
- 신규 / 확정 대기 / 확정 완료 / 변경 요청 / 노쇼 위험 / 완료 / 취소

### ❓ 자동 연동인가요?
**현재 MVP 에선 자동 연동 아닙니다.** 네이버 예약 공식 API 가 확인되지 않아,
다음 2가지 경로로 보드에 예약이 들어옵니다:

1. **수동 입력** — 상단 우측 `+ 수동 예약 추가` 버튼. 네이버 스마트플레이스 알림을 받고 운영자가 바로 등록.
2. **CSV 임포트** (TBD) — 네이버 주간 export 를 일괄 import. 로드맵 단계 7.

공식 API 가 확인되면 자동 수집 provider 로 교체됩니다 (`/settings/integrations` 의 capability 매트릭스에서 상태 변화로 확인 가능).

### 수동 예약 추가 (`+ 수동 예약 추가`)
1. 환자 이름, 전화번호 (010-1234-5678 형식), 예약 일시, 메모 입력.
2. 전화번호는 저장 시 자동으로 `010-****-5678` 로 **마스킹**.
3. 기본 상태는 `확정 대기`. 저장 후 보드에 즉시 반영.

### 카드에서 할 수 있는 것
- **상태 드롭다운**: 클릭 한 번으로 다른 컬럼으로 이동 (자동으로 감사 로그 기록)
- 환자 정보 (이름, 마스킹된 전화, 채널, 메모) 확인

### 노쇼 자동 감지
- 대시보드 / 예약 보드가 로드될 때마다 시스템이 **20분 이상 늦은 예약**을 검사.
- 해당 예약은 자동으로 `노쇼 위험` 컬럼으로 이동하고, 대시보드 상단에 관리자용 빨간 배너 표시.
- 알림톡 발송이 연동되면 관리자 휴대폰으로 "XX님 노쇼 위험, 전화 확인" 알림톡이 자동 발송됩니다.

### 자동 확정은?
`/settings/integrations` 의 capability 에서 `자동 확정` 이 "검토 필요" 상태. 공식 API 연동 전까지는 운영자가 수동으로 확정 컬럼으로 옮기는 방식.

## 6. 템플릿 관리 (`/templates`)

**언제 쓰나:** 반복 문의 자주 보일 때. 새로운 표준 문구 필요할 때.

### 왼쪽: 템플릿 테이블
- 코드 (TALK_HOURS, RESERVATION_CONFIRM 등 시스템 식별자)
- 제목 / 채널 / 컴플라이언스 등급 / 활성 여부
- 수정 / 삭제 버튼

### 오른쪽: 편집 폼
- **새 템플릿** 버튼으로 빈 폼 열기
- 기존 템플릿 "수정" 누르면 데이터가 폼에 채워짐
- 필수 입력: 코드, 의도(intent), 채널, 제목, 본문
- **컴플라이언스 등급**:
  - `standard` — 일반 검사
  - `strict` — 리뷰 답글처럼 엄격 검사 (승인 시점에 한 번 더 검사)
- **사람 검토 필수** 체크박스: 이 템플릿 사용 시 자동 발송 금지

### 변수 사용 (MVP)
`{{name}}`, `{{date}}`, `{{time}}` 같은 placeholder 는 현재 **수동 치환**입니다. (자동 치환은 발송 연동 시점에 구현)

## 7. 컴플라이언스 설정 (`/settings/compliance`)

**언제 쓰나:** 답글/메시지 작성 중 "이 문장 괜찮나?" 의심들 때.

### 왼쪽: 규칙 북
3개 드롭다운으로 확인 가능:
- **BLOCKED** (22개) — 이 표현이 있으면 무조건 거절
- **CAUTION** (9개) — 주의 표현. 자동 수정 제안 적용 가능
- **자동 수정 매핑** — "반드시" → "도움이 될 수 있도록" 등

### 오른쪽: 즉시 검사 도구
- textarea 에 검사할 문장 붙여넣기
- "검사 실행" 클릭
- 결과: approved / rejected / revision_required + 발견된 이슈 목록 + 수정된 문장

### 활용법
답글 초안을 리뷰 인박스 밖에서 미리 검사하고 싶을 때. 또는 직원 교육용.

## 8. 연동 설정 (`/settings/integrations`)

**언제 쓰나:** 연동 상태 확인. 실제 편집은 아직 불가 (읽기 전용).

### 보여주는 것
각 채널(네이버 예약/톡톡/리뷰, 카카오 비즈/채널)의 capability 매트릭스:
- `지원` (녹색) — 시스템이 공식 방식으로 지원
- `수동` (노란색) — 운영자 수동 처리 필요
- `검토 필요` (회색) — 공식 API 미확인 / 연동 전

**현재 MVP 에선 대부분 `수동` 또는 `검토 필요`** 입니다. 연동 진행은 `docs/INTEGRATION_ROADMAP.md` 참조.

## 9. 감사 로그 (`/logs`)

**언제 쓰나:** "누가 저 답글 승인했지?" / "언제 예약 상태가 바뀌었지?" 궁금할 때. 또는 분쟁 대응 시.

### 보여주는 것
시간 역순 테이블:
- 시각 (hover 하면 정확한 타임스탬프)
- 행위자 (user 이름, 시스템 자동이면 "system")
- 엔티티 (예: `Review/rv_3`, `Template/tpl_price`)
- 액션 (예: `review.draft_approved`, `conversation.escalated`)
- 변경 (before/after JSON — "자세히" 클릭해서 펼치기)

### 기록되는 주요 액션
- `review.draft_generated` / `review.compliance_checked` / `review.draft_approved` / `review.posted`
- `conversation.classified` / `conversation.updated` / `conversation.escalated`
- `reservation.updated` / `reservation.confirmed`
- `template.created` / `template.updated` / `template.deleted`

## 10. 자주 하는 실수 & 팁

### 실수 모음
1. **서버 재시작 후 데이터가 사라짐** → 정상입니다. mock store라 메모리에만 저장.
2. **"초안 생성" 을 아무리 눌러도 결과가 똑같음** → 정상. 결정형 엔진이라 같은 리뷰엔 같은 답.
3. **BLOCKED 표현이 있는데 승인 버튼 눌렀더니 에러** → 정상. 표현을 수정해야 합니다.
4. **네이버에 자동으로 답글이 안 올라감** → 아직 연동 전. "등록 완료 처리" 는 운영자가 직접 등록한 후 상태 기록용.

### 운영 팁
- 리뷰 답글은 **1인 운영이라도 최소 2단계 검토** 추천: 초안 생성 → 눈으로 한 번 → 컴플라이언스 검사 → 승인.
- `strict` 등급 템플릿은 의료법 리스크 높은 문구(비용 안내, 부정 리뷰 응대)에 사용.
- 매일 퇴근 전 `/logs` 를 한 번 훑어보면 하루 작업 리뷰가 됩니다.
